# P3：逐连接心跳与异步存储交付

日期：2026-10-23。范围依据本轮 P3 v0.2 与总则；历史恢复沿用 P2，不引入新同步器或消息队列。

## 连接行为

- ping 只回复发起连接。保留顶层 `pong.timestamp`（服务端时间），新增可选 `pingTimestamp` 回显；接受顶层或 `payload.timestamp`。无时间戳返回普通 pong，两处冲突或字段类型错误返回当前连接的 `INVALID_JSON`。
- 非对象 JSON、错误的 type/payload/请求身份受控拒绝，单个坏帧不关闭连接、不回显原始输入。输入拒绝错误只回当前连接；空白正文仍为 `EMPTY_MESSAGE`，已接收轮次的结果与失败仍沿用账户广播。
- 三端把回显关联到当前连接的在途 ping，重连清空状态，旧连接的打开、消息、失败和关闭回调不能改变新连接。无回显旧 pong 保留兼容；有回显时必须匹配，不能用不相干回显重置超时。
- Linux/Windows 延续 25 秒周期，连续三次未获回应后关闭并走既有退避重连。Android 增加同样的应用心跳响应判断，同时为 WS 专用 OkHttp 实例启用 25 秒协议 ping；发送入队不再等于存活。
- 自动重连、鉴权续签重连都会要求既有完整历史恢复。Android 继续由已有 Connected 消费方补拉；不改变 P2 的游标与落库规则。

## 存储边界盘点

| 实际入口 | 本期处理 |
|---|---|
| 积分余额/概览/流水、等级、补签卡查询与使用、互动菜单 | 在现有线程执行设施中调用完整同步服务方法 |
| 管理配置读写、进度查询、积分调整、回填与重置 | 同上；同步调用入口保留 |
| 普通聊天活动、互动成功奖励、首次补签卡发放 | 完整服务方法在线程内完成，推送仍在事件循环 |
| 新旧互动扣款、退款、持久补偿 | 账本读改写不拆分；可靠扣款的 SQL 门闩与 JSON 回调保持同次线程调用和原锁序 |
| 断签扫描、预警/断签幂等标记、月度卡与纪念日 | 所有可达文件事务离开事件循环；标记的读改写同次调用 |
| 心情调度的用户枚举、兼容历史/事实写入、时间线追加 | 移出事件循环；追加复用取消安全调用 |
| WS JSON、图片 Base64/PIL 校验、可靠生成的图片解码 | 在线程执行；保留原图、EXIF、校验次序和原有大小/像素限制 |

`store_call` 在重复取消时仍等待原线程完成，再传播取消。不会把取消或 await 超时当作线程已停止。恢复继续核对原请求的真实扣款/退款幂等键。

积分/进度文件的线程锁与文件锁共用最多 10 秒的获取预算；配置发布锁也有界。共享 JSON 文件入口在线程池外串行等待，准入等待最多 10 秒，防止同账户并发把默认线程池占满。HTTP 锁繁忙返回受控 503/50301 与原请求重试动作；互动锁超时归为存储故障而非 AI 超时。

## 测试复用与补充

- 扩展 `test_ws_lock_error.py`：双连接隔离、旧 ping、畸形帧后继续 ping、真实积分文件锁 2 秒时的往返延迟；用三个线程并发八个查询，另一个线程任务仍能及时执行。
- 扩展 `test_storage_failures.py`、`test_reliable_interaction.py`：线程锁/文件锁超时、扣款与退款在等锁/落盘两阶段被重复取消后核账，重放保持各一笔；复用原 JSON/SQL 与互动 fixture。
- 原图片拒绝测试过去只监听广播替身，现改为检查当前 socket 并增加不广播断言；错误码、整批拒绝和不入库断言保留。`test_unified_api.py` 验证真实统一入口的锁错误信封。
- 扩展 Linux 原 `selftest.ts` 与 Windows 原 `NetworkFrameContractTests.cs`，使用真实 loopback WS 验证回显和旧回调；Windows 用真实 25 秒定时器验证无 pong 后重新连接、清空心跳和发出完整历史恢复信号。
- Android 网络模块原先没有 WS 生命周期测试，因此仅新增 `OkHttpBotWebSocketClientTest.kt`，使用 OkHttp 自带接口替身验证失联恢复调度、旧回调隔离和旧 pong。只补 JUnit 测试依赖，不引入 MockWebServer 或新测试框架。
