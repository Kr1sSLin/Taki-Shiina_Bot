# TKS 互动积分等级体系 —— 接口契约与客户端对接说明

> 对应 PRD《TKS_互动积分等级体系_PRD_v2.md》第 4、5、6、8、9 节。
> 服务端实现：`Taki_Shiina_Bot/`（由 `ws_api.py` 进程提供，见文末部署说明）。
> 客户端实现：`Android_AI_Assistant/`。

---

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 前缀 | `/api/v1`（与现有 `api/v1/` 版本化路由风格一致） |
| 鉴权 | 复用现有 JWT：`Authorization: Bearer <accessToken>`，叠加设备白名单校验（PRD §8） |
| 响应信封 | `{"code": 0, "message": "ok", "data": {...}, "traceId": "..."}` |
| 业务错误 | HTTP 200 + `code != 0`（便于客户端按 code 判定业务结果）；鉴权失败返回 HTTP 401；参数缺失返回 HTTP 400 |
| 幂等 | 互动发送必须携带 `requestId`，服务端以其为幂等键（PRD FR-13 / EDGE-1） |
| 时间基准 | 一切“自然日”以**业务时区**判定，默认 UTC+8（PRD FR-10 / EDGE-3，可用 `BIZ_TZ_OFFSET_HOURS` 覆盖） |

### 1.1 业务错误码

| code | 含义 | 触发场景 |
|---|---|---|
| 0 | 成功 | — |
| 40001 | 参数错误 | 缺少 `itemId` / `targetDate` |
| 40101 | 鉴权失败 | token 无效/过期 |
| 40201 | 积分不足 | 互动发送余额不足（PRD FR-3） |
| 40202 | 物品不存在或已下架 | `is_active=false` 或 id 不存在 |
| 40204 | AI 调用最终失败（已退款） | 重试超限或超过 15 秒总兜底（PRD FR-9 / EDGE-2） |
| 40205 | 补签卡不足 | 无 `AVAILABLE` 卡片（PRD 6.2） |
| 40206 | 该日期已有有效对话记录 | 重复补签同一天（PRD 6.2） |
| 40207 | 目标日期非法 | 格式错误或晚于今天 |

## 2. REST 接口

### 2.1 `GET /api/v1/interaction/items`

互动菜单物品列表（FR-1 / FR-4 / FR-5：简单平铺列表，按 `sortOrder` 排序，不设每日上限）。

```json
{
  "code": 0, "message": "ok", "traceId": "trace_x",
  "data": {
    "balance": 16,
    "dailyLimit": null,
    "items": [
      {"id": "coffee", "name": "咖啡", "icon": "☕", "iconUrl": "",
       "costPoints": 5, "sortOrder": 10, "affordable": true}
    ]
  }
}
```

> 客户端据此对 `affordable=false` 的物品置灰（US-1）。

### 2.2 `POST /api/v1/interaction/send`

发送互动物品：扣积分 → 组装 Prompt（含当前 session 历史）→ 调用 DeepSeek → WS 推送回复（FR-2/3/6/7/8）。

请求体：

```json
{"itemId": "coffee", "requestId": "客户端 UUID（幂等键）", "text": "可选附言：输入框里的文字"}
```

> `text` 为 O5 附言：带附言时拼进 user 回合 `（☕咖啡）今天好累啊`，只回一条；
> 不带附言时，服务端会自动带上「已发出但还在防抖窗口里」的最近文字（见 4.4）。

成功响应（同时会先收到 `chat.typing`，再收到 `chat.reply.stream`，`messageKind=interaction`）：

```json
{
  "code": 0, "message": "ok",
  "data": {
    "success": true, "itemId": "coffee", "requestId": "req-1",
    "balance": 16, "charged": 5, "refunded": false, "duplicate": false,
    "item": {"id": "coffee", "name": "咖啡", "icon": "☕", "costPoints": 5},
    "reply": "啧……谁让你买的。\n收下了。", "messageId": "uuid",
    "timerInstruction": {"target": "02:00", "text": "两点了"}
  }
}
```

失败响应：

| code | data 关键字段 | 客户端表现 |
|---|---|---|
| 40201 | `balance`, `charged=0` | 提示“积分不足”，不展示 Taki 回复 |
| 40202 | — | 提示物品已下架，刷新菜单 |
| 40204 | `refunded=true`, `fallbackText` | 展示兜底文案（服务端同时通过 WS 推送该文案），提示积分已退回 |

> **回复通道**：以 WS 推送为主，HTTP 响应同步返回兜底（需求方确认）。
> 客户端按 `requestId` 去重，避免同一条回复展示两次。

### 2.3 `GET /api/v1/points/balance`

```json
{"code": 0, "data": {"balance": 16, "updatedAt": 1757000000000}}
```

### 2.4 `GET /api/v1/points/overview`

客户端首屏聚合接口（余额 + 等级 + 补签卡）：

```json
{
  "code": 0,
  "data": {
    "balance": 16,
    "balanceUpdatedAt": 1757000000000,
    "level": {
      "levelCode": "PANDA_LV2", "levelName": "好奇宝宝",
      "prevLevelCode": "PANDA_LV1", "continuousDays": 7,
      "changeType": "UPGRADE", "changeSource": "ACTIVITY",
      "highestLevelCode": "PANDA_LV2",
      "lastValidDate": "2026-09-10", "gapDays": 0, "breakDeadlineDate": "2026-09-15",
      "nextLevelCode": "PANDA_LV3", "nextLevelName": "竹林新秀",
      "nextLevelThresholdDays": 15, "daysToNextLevel": 8,
      "levelUpdatedAt": 1757000000000,
      "isDefaultLevel": false, "streakDates": ["2026-09-04", "..."],
      "availableMakeupCards": 2
    },
    "makeupCard": {
      "available": 2, "used": 0, "totalGranted": 2,
      "maxAvailable": 12, "monthlyGrant": 1,
      "lastGrantedMonth": "2026-09", "currentMonthGranted": true, "atLimit": false
    }
  }
}
```

> `levelName` 在 `levelCode=NONE` 时为空字符串：EDGE-7 规定默认态**不设专属文案**，
> 客户端对“断签回落”和“从未升级的新用户”共用同一套默认展示。

### 2.5 `GET /api/v1/points/history?page=1&pageSize=20&reasonCode=ITEM_SEND`

```json
{
  "code": 0,
  "data": {
    "items": [
      {"id": 12, "user_id": "u1", "change_amount": -5, "reason_code": "ITEM_SEND",
       "balance_after": 15, "related_item_id": "coffee",
       "idempotency_key": "item_send:u1:req-1", "created_at": 1757000000000,
       "business_date": "2026-09-10"}
    ],
    "total": 12, "page": 1, "pageSize": 20, "hasMore": false
  }
}
```

`reason_code` 取值：`DAILY_FIRST_CHAT`(+1) / `STREAK_3_DAY`(+3，循环) / `ANNIVERSARY`(+100) /
`ITEM_SEND`(负数) / `ITEM_REFUND`(正数，退回)。

### 2.6 `GET /api/v1/level/status`

返回结构同 2.4 中的 `level` 对象，并额外附带 `availableMakeupCards`。
客户端展示：当前等级、距下一等级剩余天数（FR-15）；`breakPending` 场景由 WS `streak.warning` 驱动（FR-18）。

### 2.7 `GET /api/v1/level/config`

等级阈值表 + 规则（供等级说明页渲染，无需发版）：

```json
{
  "code": 0,
  "data": {
    "levels": [{"level_code": "PANDA_LV1", "level_name": "初生熊猫", "threshold_days": 3, "sort_order": 10}],
    "defaultLevelCode": "NONE", "defaultLevelName": "",
    "makeupCardMax": 12, "breakGapDays": 5, "warningGapDays": [3, 4]
  }
}
```

### 2.8 补签卡

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/points/makeup-card` | 可用张数、上限、本月是否已发放 |
| GET | `/api/v1/points/makeup-card/candidates?limit=120` | 可补签日期候选（缺失自然日，按时间倒序），见下 |
| POST | `/api/v1/points/makeup-card/use` | 请求体 `{"targetDate": "2026-09-11"}`；**必须由用户主动点击触发**（FR-20） |
| GET | `/api/v1/points/makeup-card/history?page=1&pageSize=20` | 发放/使用历史，便于核对跨月结转（FR-21） |

候选日期响应（`daysAgo` 便于客户端文案“3 天前”）：

```json
{"code": 0, "data": {
  "items": [{"date": "2026-09-11", "daysAgo": 3}],
  "total": 5, "firstActivityDate": "2026-09-01", "available": 2
}}
```

> 候选列表只是便捷入口：服务端 `use_card` 仍接受**任意**合法历史日期（FR-22）。

使用成功响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "success": true, "availableCards": 1, "targetDate": "2026-09-11",
    "card": {"id": 3, "granted_month": "2026-09", "status": "USED", "used_for_date": "2026-09-11"},
    "level": {"levelCode": "PANDA_LV2", "changeType": "RESTORE", "continuousDays": 11, "...": "..."}
  }
}
```

> 校验失败返回 code 40205 / 40206 / 40207，`data.success=false`；失败不消耗卡片。

### 2.9 后台配置（运营侧，PRD §九）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/gamification-config` | 读取全部可配置项 |
| PUT | `/api/v1/admin/gamification-config` | 局部更新，如 `{"interaction_items":[...]}`、`{"points_rules":{...}}` |
| POST | `/api/v1/admin/gamification-config/reset` | 恢复内置默认 |
| GET | `/api/v1/admin/user-progress?userId=u1` | 只读对账视图 |
| GET | `/api/v1/admin/interaction-prompt-preview?itemId=coffee&text=附言` | **查看真实发给 DeepSeek 的完整 messages**（含人设 prompt 与历史），改完模板可立刻核对 |
| POST | `/api/v1/admin/points/adjust` | **测试用**：改积分余额（见下） |
| POST | `/api/v1/admin/progress/backfill` | **测试用**：构造最近 N 天有效对话（免等天数测等级/断签） |
| POST | `/api/v1/admin/progress/reset` | **测试用**：清空连续天数与等级（保留积分） |

> 也可直接编辑 `Taki_Shiina_Bot/config/gamification_config.json`（按 mtime 热加载，无需发版）。
> EDGE-9：Prompt 模板在请求发起时快照，后台更新只影响之后新发起的互动。
> 后三个测试接口由 `ENABLE_ADMIN_TEST_API=0` 一次性关闭（默认开启）。

#### 测试接口用例

```bash
# 登录取 token（curl 也算一台设备，受 AUTH_MAX_DEVICES 限制）
TOKEN=$(curl -s https://takishiinabot.top/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"你的用户名","password":"你的密码","deviceId":"curl-debug"}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["accessToken"])')

# ① 把积分设为 500（走正规流水，reason_code=ADMIN_ADJUST，流水页可见）
curl -s -X POST https://takishiinabot.top/api/v1/admin/points/adjust \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"balance": 500}'
# → {"code":0,"data":{"balance":500,"change":500,"reasonCode":"ADMIN_ADJUST",...}}

# 加/减（增量，可为负；扣成负数会被拒绝）
curl -s -X POST .../admin/points/adjust -d '{"amount": 1000}'
curl -s -X POST .../admin/points/adjust -d '{"amount": -100}'

# ② 构造连续 15 天（默认不发积分，只影响等级 → 立即变「竹林新秀」）
curl -s -X POST https://takishiinabot.top/api/v1/admin/progress/backfill \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"days": 15}'
# 需要同时验证积分发放时加 {"awardPoints": true}（按天正规补发，会出现 DAILY_FIRST_CHAT / STREAK_3_DAY 流水）

# ③ 重置连续天数与等级（积分保留），可反复测「断签 → 补签卡挽回」
curl -s -X POST .../admin/progress/reset -d '{}'
curl -s -X POST .../admin/progress/reset -d '{"clearMakeupCards": true}'   # 连补签卡一起清掉
```

#### ⚠️ 客户端字段名契约（改接口时务必注意）

客户端的 DTO 是按字段名反序列化的，**字段名写错不会报错，只会静默变成默认值**（曾因此让等级表 7 条记录的
`levelCode` 全为空串，客户端列表重复 key 直接闪退）。当前契约：

| 接口 | 字段风格 | 具体 |
|---|---|---|
| `/level/config` 的 `levels[]` | **snake_case** | `level_code` `level_name` `threshold_days` `sort_order`（PRD 5.5 表字段） |
| `/points/history` 的 `items[]` | **snake_case** | `user_id` `change_amount` `reason_code` `balance_after` `related_item_id` `created_at` `business_date` |
| `/points/makeup-card*` 的卡记录 | **snake_case** | `user_id` `granted_month` `used_for_date` `used_at` `created_at` |
| 其余所有字段 | camelCase | 如 `defaultLevelCode`、`makeupCardMax`、`costPoints`、`availableCards` |

回归测试 `test_field_name_contract_for_client_dtos` 会守住这些键名，服务端改名会立刻失败。

## 3. WebSocket 事件（复用现有 `/ws/chat` 通道）

### 3.1 互动回复

沿用普通聊天消息事件，新增 `messageKind` 区分：

```json
{"type": "chat.typing", "payload": {"typing": true, "stage": "interaction"}}
{"type": "chat.reply.stream", "requestId": "req-1", "payload": {
  "delta": "", "done": true, "messageId": "uuid",
  "finalContent": "啧……谁让你买的。",
  "messageKind": "interaction",          // interaction_failed 表示兜底文案
  "interactionItemId": "coffee", "interactionItemName": "咖啡", "interactionItemIcon": "☕",
  "interactionFailed": false, "timestamp": 1757000000000
}}
```

### 3.2 积分变动 `points.changed`

```json
{"type": "points.changed", "payload": {
  "ledgerId": 12, "reasonCode": "DAILY_FIRST_CHAT", "changeAmount": 1,
  "balanceAfter": 16, "balance": 16, "relatedItemId": null,
  "businessDate": "2026-09-10", "timestamp": 1757000000000
}}
```

> EDGE-4：三条规则各自独立事件，不合并金额；客户端可逐条展示或只更新余额。

### 3.3 等级变化 `level.changed`

```json
{"type": "level.changed", "payload": {
  "levelCode": "PANDA_LV2", "levelName": "好奇宝宝", "prevLevelCode": "PANDA_LV1",
  "continuousDays": 7, "changeType": "UPGRADE",
  "changeSource": "ACTIVITY", "highestLevelCode": "PANDA_LV2",
  "gapDays": 0, "breakDeadlineDate": "2026-09-15",
  "nextLevelCode": "PANDA_LV3", "nextLevelName": "竹林新秀",
  "daysToNextLevel": 8, "timestamp": 1757000000000
}}
```

`changeType` 语义（EDGE-11，客户端文案需区分）：

| 值 | 含义 | 建议文案 |
|---|---|---|
| `UPGRADE` | **首次**达成该等级 | 升级庆祝（弹窗/动画 + 本地通知） |
| `RESTORE` | 曾经达成过，多为补签回溯挽回 | 克制的“等级已恢复”提示 |
| `RESET` | 断签回落，等级清零 | “连续陪伴中断，等级已重置”，并提示可使用补签卡 |

> 通知范围：该账号**全部在线设备**（FR-16 / EDGE-8，不做活跃设备过滤）。

### 3.4 断签提前提醒 `streak.warning`

```json
{"type": "streak.warning", "payload": {
  "levelCode": "PANDA_LV2", "levelName": "好奇宝宝", "continuousDays": 7,
  "gapDays": 3, "remainingDays": 2, "deadlineDate": "2026-09-12",
  "timestamp": 1757000000000
}}
```

连续 3～4 天未对话时推送（FR-18）；用户当日完成一次对话后提醒自动解除。

### 3.5 补签卡变动 `makeup_card.changed`

```json
{"type": "makeup_card.changed", "payload": {
  "reason": "MONTHLY_GRANT", "available": 2, "used": 0, "totalGranted": 2,
  "maxAvailable": 12, "lastGrantedMonth": "2026-09", "timestamp": 1757000000000
}}
```

`reason`：`MONTHLY_GRANT`（每月发放/新用户首发） / `USED`（使用）。

## 4. 互动物品 → DeepSeek 的完整 Prompt

组装逻辑：`handlers/interaction_handler.py::_build_messages`（PRD FR-6 / FR-7）。

| # | role | 内容 |
|---|---|---|
| 0 | `system` | 人设 system prompt（`PromptService.get_system_prompt`，约 3.3k 字：椎名立希人设 + 说话习惯 + **【立希当前状态】心情**）+ **时间块** + 天气 + 三条时间强制规则 |
| 1…n | `user`/`assistant` | 当前 session 最近 10 条历史（取 `──── 新的一天 ────` 之后，并做污染尾句清洗），每条前置 `【MM-DD HH:MM】` 时间戳 |
| n+1 | `system` | 【强制提醒】保持人设/禁止动作叙事 + 【注意力锚定】+【去重要求】+【禁止时间戳】 + 可选【他刚刚还说】 + **渲染后的【互动事件】指令** |
| n+2 | `user` | `（{icon}{name}）`；有附言时追加为 `（☕咖啡）今天好累啊` |

### 4.1 时间块由服务端判定（不再让模型自己猜）

四个场景（普通聊天 / 互动 / 早晚安问候 / REST 聊天）共用 `time_utils.build_time_block()`：

```text
【当前北京时间】：02:14
【当前时段】：深夜（系统已判定，直接采用，不要再自行推断时段）
```

| 时段 | 区间（业务时区，默认 UTC+8） |
|---|---|
| 深夜 | 23:00–04:59 |
| 清晨 | 05:00–08:59 |
| 上午 | 09:00–11:59 |
| 下午 | 12:00–17:59 |
| 晚上 | 18:00–22:59 |

> 问候任务另加一条兜底：本任务固定为「早安 / 深夜问候」，若时段标签与任务不完全一致（早安窗口最晚可延到午前），**以任务为准**。

### 4.2 心情（立希当前状态）刷新机制

| 机制 | 说明 |
|---|---|
| S1 整点主动刷新 | `ws_api.scene_refresh_scheduler()`：每个自然小时、整点后随机 0~5 分钟调 `PromptService.refresh_scene()`；用户请求永远命中热缓存，不额外等 LLM |
| E5 过期兜底 | `get_random_scene()` 发现 `expires_at` 已过 → **先返回旧心情**，后台异步重建（60 秒防抖），下一条消息生效 |
| S3 手动触发 | `POST /internal/scene/refresh`（仅本机 + 内部 token），见 4.4 |

### 4.3 各物品的【互动事件】指令

可在 `config/gamification_config.json` 的 `prompt_templates` 中改，改完即时生效：

```text
● 咖啡（5 分）
【互动事件】Kris 刚刚送了你一杯☕咖啡（消耗 5 积分）。
先看上文两处，再决定台词：
1）【当前时段】（系统已判定，直接用）：
   - 深夜：默认他也在陪你熬，用「既然都送来了」的共犯语气收下，别劝他去睡。
   - 清晨 / 上午 / 下午 / 晚上：可以吐槽他挑时间、乱花钱，但照样收下，口气随刚才聊的内容走。
2）【立希当前状态】里的「情绪底色」：心情不错就高兴地收下（是立希式别扭的高兴，不是撒娇甜话）；心情不好就一边嫌弃一边收下。
反应方向：先别扭一句，然后收下；不要写「不要」「你自己喝」这类硬拒；不要直接说出自己的状态，心情只体现在语气里。
输出要求：1～3 行短句，总长 40 字以内；严禁动作叙事或星号描写。

● 泡面（7 分）/ ● 手柄（13 分）—— 维持原样，见 config 文件

● 白龙（16 分，图标 🚬）
【互动事件】Kris 刚刚送了你一只🚬白龙（消耗 16 积分）——白龙是烟的代称，你清楚他递过来的是什么。
先看上下文挑一种反应，只写一种，不要两种都写：
```

### 4.4 「文字 + 送出互动礼物」的合并规则（B 方案，只回一条）

| 场景 | 服务端行为 |
|---|---|
| 输入框有文字时点礼物 | 客户端把文字作为 `text` 附言随 `POST /interaction/send` 提交 → 拼进 user 回合 `（☕咖啡）今天好累啊`；**只回一条**；成功后客户端清空输入框（失败保留，用户仍可正常发送） |
| **先发文字、防抖未到就点礼物** | 服务端**等静默窗口结束**（8 秒；距上次回复 <40 秒则 20 秒；最长等 25 秒），把窗口内的用户消息**摘走**（`message_buffer.pop`）并合进本次礼物回复 → 聊天 worker 拿不到这批消息，**不会再产生第二条回复**；被摘消息的 `requestId` 通过 `requestIds` 一并下发，客户端据此把那些气泡标记为"已发送"（否则会永远停在"发送中"） |
| 两者同时存在 | **附言优先**，不再摘缓冲，避免同一句话出现两次 |
| 等待期间 | 先推 `chat.typing`（`stage=interaction_merge`）让客户端显示"思考中"；等待出错则降级为立即回复，不影响扣分与回复 |

> 代价：送礼响应时间 = 静默窗口剩余时间 + DeepSeek 调用（最长约 25 + 15 秒）；
> 若那条聊天已被聊天 worker 取走（缓冲已空）则**不等待**，立即回复。

`POST /interaction/send` 成功响应会多出两个字段：

```json
{"mergedCount": 2, "mergedRequestIds": ["chat-1", "chat-2"]}
```

随时核对**线上真实内容**（含人设 prompt 与你的聊天历史，不产生任何副作用）：

```bash
# 也可以带附言预览合并结果
curl -s "https://takishiinabot.top/api/v1/admin/interaction-prompt-preview?itemId=coffee&text=今天好累啊" \
  -H "Authorization: Bearer $TOKEN"
# → data.messages 即原样发给 DeepSeek 的 messages 数组；data.promptTemplate 为该物品的指令模板

# 手动刷新「立希当前状态」（仅本机）
curl -s -X POST "http://127.0.0.1:8001/internal/scene/refresh" -H "X-Internal-Token: $BOT_WS_TOKEN"
curl -s -X POST "http://127.0.0.1:8001/internal/scene/refresh?userId=kris" -H "X-Internal-Token: $BOT_WS_TOKEN"
```

## 5. 部署说明（重要）

积分/等级数据由 **`ws_api.py` 进程独占持有**：App 内所有用户对话都经 WebSocket 抵达该进程，
互动回复又必须通过该进程的 `ACTIVE_CONNECTIONS` 推送，且定时任务与数据同进程才能保证“改完即推”。
因此新增的 REST 路由挂在 `ws_api` 的 FastAPI app 上，反向代理需要把以下路径也指向该服务：

```nginx
# 现有
location /api/v1/  { proxy_pass http://127.0.0.1:8000; }   # http_api.py：聊天历史/记忆/城市
location /ws/      { proxy_pass http://127.0.0.1:8001; }   # ws_api.py：WebSocket

# 新增（积分 / 等级 / 互动 / 后台配置）
location /api/v1/interaction/ { proxy_pass http://127.0.0.1:8001; }
location /api/v1/points/      { proxy_pass http://127.0.0.1:8001; }
location /api/v1/level/       { proxy_pass http://127.0.0.1:8001; }
location /api/v1/admin/       { proxy_pass http://127.0.0.1:8001; }
```

> 注意：`http_api.py` 的 `POST /api/v1/chat`（REST 对话）不参与积分结算——
> App 的对话链路全部走 WebSocket；如需让 REST 对话也计分，应把该接口一并迁到 `ws_api` 进程。
