# 隐私防护

根 `.gitignore` 排除本机环境配置、签名密钥、迁移备份和本机工具设置。
经过脱敏的 `.env.example` / `.env.*.example` 可以提交。
忽略规则不保护已经跟踪的文件，也不保护直接压缩整个工作目录的操作。

启用本地提交检查（每个克隆执行一次）：

```sh
git config --local core.hooksPath .githooks
```

手动检查 Git 暂存区：

```sh
python scripts/privacy_check.py --staged
python scripts/privacy_check.py
```

无参数检查全部暂存区文件；`--staged` 检查本次变更。检查直接读取暂存区
blob，不读取可能已被修改的工作副本；输出文件位置和规则名，不输出凭据。
CI 执行同样检查及备份迁移回归测试。这些规则针对已知敏感文件路径、常见
凭据格式和本机用户路径，不能保证发现所有秘密，也不替代完整历史扫描。

后端迁移开启 `DATA_BACKUP_ON_MIGRATE=1` 时，先生成
`原文件.bak.随机后缀.enc`，使用当前 `DATA_ENC_KEY` 加密并验证可解密恢复，
然后替换原文件。备份或验证失败时保留原文件；严格读取接口抛出异常，
兼容读取接口记录错误并返回原数据。原文件替换失败时保留已验证的加密备份。
备份和原文件使用同一密钥，恢复时需要妥善保管该密钥。

生产运行时将 `BOT_DATA_DIR` 配置到仓库外的受控目录；迁移已有数据时应停服、
备份并验证恢复后再切换。该设置不自动移动已有文件。源码目录中的 `.env`
及其部署配置备份仍需受控权限，不能随源码目录一并分享。

历史隐私清理需覆盖相关分支、标签和旧文件路径，并复核 reflog、残留对象、
发行附件和外部备份。修改 `.gitignore` 或创建删除提交不会移除旧历史。
